# Laraseed Generator V3 — Authentication & Guard Isolation

This document provides the definitive guide for integrating, configuring, and securing user authentication within Web capabilities generated by **Laraseed Generator V3**.

---

## 1. Architectural Philosophy: Decoupled Authentication

Laraseed Web capabilities are designed with a **decoupled authentication architecture**:

```
+-----------------------------------------------------------------------------------+
|                           AUTHENTICATION ISOLATION ARCHITECTURE                   |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  [ Webkul Admin ] -----------> Guard: 'admin' (Fixed, Session, Admin ACL)         |
|                                                                                   |
|  [ Web Package: Portal ] ----> Guard: 'customer' (Isolated, Session/Sanctum)     |
|  [ Web Package: Store ] -----> Guard: 'user'     (Isolated, Custom Provider)      |
|  [ Web Package: Docs ] ------> Mode:  Public     (No Guard, Zero Auth Logic)      |
|                                                                                   |
|  [ Core Redirect Resolver ] -> Directs guests to the exact matching login route   |
+-----------------------------------------------------------------------------------+
```

### Core Security Principles
1. **Public by Default:** Web packages default to public mode (`'auth.enabled' => false`). No login/logout forms or protected routes are registered until explicitly enabled.
2. **Zero Admin Guard Coupling:** Web packages never hijack the `admin` guard, protecting admin session security.
3. **No Embedded Auth Tables:** Web packages consume guards and user providers configured in `config/auth.php` or provided by companion packages (e.g. `customer`, `members`).
4. **CSRF-Protected POST Logout:** Logout actions MUST use HTTP `POST` with CSRF tokens. Insecure `GET` logout routes are strictly rejected.
5. **Strict Redirect Isolation:** Unauthenticated guest requests are redirected exclusively to their respective package login route and never leak across packages or Admin.

## 2. Configuration Schema (`src/Web/Config/web.php`)

```php
return [
    // ...

    /**
     * Optional Web Authentication Configuration.
     * Default: false (Public website mode).
     */
    'auth' => [
        /**
         * Enable or disable authentication integration.
         */
        'enabled' => false,

        /**
         * The authentication guard configured in config/auth.php.
         * Example: 'customer', 'member', 'portal', 'user'.
         */
        'guard' => null,

        /**
         * Optional Laraseed package ID providing authentication.
         * Example: 'customer', 'members'.
         */
        'provider_package' => null,

        /**
         * Named routes for login and logout actions.
         * Logout route MUST support HTTP POST with CSRF protection.
         */
        'routes' => [
            'login'  => null,
            'logout' => null,
        ],
    ],
];
```

## 3. Step-by-Step: Enabling Authentication in a Web Package

### Step 1: Configure a Guard in `config/auth.php` (if not using standard `user`)
```php
'guards' => [
    'customer' => [
        'driver'   => 'session',
        'provider' => 'customers',
    ],
],

'providers' => [
    'customers' => [
        'driver' => 'eloquent',
        'model'  => App\Models\Customer::class,
    ],
],
```

### Step 2: Enable Auth in `packages/Acme/Portal/src/Web/Config/web.php`
```php
'auth' => [
    'enabled'          => true,
    'guard'            => 'customer',
    'provider_package' => null,
    'routes'           => [
        'login'  => 'customer.login',
        'logout' => 'customer.logout',
    ],
],
```

### Step 3: Protect Routes Using the Package Middleware Alias
Apply the package-owned middleware `{package_key}_auth` in `src/Web/Routes/web.php`:

```php
Route::middleware('acme_portal_auth')->group(function () {
    Route::get('account/dashboard', [AccountController::class, 'dashboard'])->name('account.dashboard');
    Route::get('account/settings', [AccountController::class, 'settings'])->name('account.settings');
});
```

## 4. Package-Owned Auth Middleware (`AuthenticateWeb.php`)

The generated middleware at `src/Web/Http/Middleware/AuthenticateWeb.php` validates all configuration dependencies before executing the request:

```php
namespace {{ NAMESPACE }}\Web\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Route;

class AuthenticateWeb
{
    public function handle(Request $request, Closure $next)
    {
        $authConfig = config('{{ PACKAGE_KEY }}_web.auth', []);
        $enabled = (bool) ($authConfig['enabled'] ?? false);

        if (! $enabled) {
            throw new \RuntimeException(
                'Authentication is disabled for package [{{ PACKAGE_KEY }}]. To protect routes, configure and enable auth in config/{{ PACKAGE_KEY }}_web.php.'
            );
        }

        $guard = $authConfig['guard'] ?? null;
        if (! $guard || ! config("auth.guards.{$guard}")) {
            throw new \RuntimeException(sprintf(
                'Authentication configuration error: Package [%s] specifies guard [%s], which is not defined in config/auth.php.',
                '{{ PACKAGE_KEY }}',
                $guard ?? 'null'
            ));
        }

        if (! auth()->guard($guard)->check()) {
            $loginRoute = $authConfig['routes']['login'] ?? null;
            if (! $loginRoute || ! Route::has($loginRoute)) {
                throw new \RuntimeException(sprintf(
                    'Authentication configuration error: Package [%s] requires a valid named login route, but route [%s] is not defined.',
                    '{{ PACKAGE_KEY }}',
                    $loginRoute ?? 'null'
                ));
            }

            if ($request->expectsJson()) {
                return response()->json(['message' => 'Unauthenticated.'], 401);
            }

            return redirect()->guest(route($loginRoute));
        }

        return $next($request);
    }
}
```

## 5. POST Logout with CSRF Protection

Laraseed strictly enforces that all logout actions execute over HTTP `POST` with a valid CSRF token.

### Why GET Logout is Insecure
- Vulnerable to cross-site request forgery (CSRF) via simple `<img>` or `<script>` tags embedded on malicious external websites.
- Search engine crawlers and prefetchers may inadvertently trigger user logouts.

### Secure Logout Form in `header.blade.php`
```blade
@if (! empty($authConfig['routes']['logout']) && \Illuminate\Support\Facades\Route::has($authConfig['routes']['logout']))
    <form method="POST" action="{{ route($authConfig['routes']['logout']) }}" class="inline m-0">
        @csrf
        <button
            type="submit"
            class="rounded-lg px-3 py-1.5 text-xs font-semibold text-gray-700 hover:bg-gray-100 dark:text-gray-300 dark:hover:bg-gray-800 border border-gray-200 dark:border-gray-700 cursor-pointer bg-transparent transition-colors"
        >
            @lang('{{ PACKAGE_KEY }}_web::app.web.auth.logout')
        </button>
    </form>
@endif
```

> [!WARNING]
> If a developer configures a named logout route that only accepts `GET` requests, `AuthenticateWeb` throws a diagnostic `RuntimeException` during request handling.

## 6. Authentication Redirect Scope & Isolation

When an unauthenticated guest requests a protected URL, Laraseed's `AuthenticationRedirectResolver` determines where the user should be redirected:

```
                                  +---------------------------------------+
                                  |     Incoming Guest Request            |
                                  +---------------------------------------+
                                                      |
                         +----------------------------+----------------------------+
                         |                                                         |
               [Route: /admin/leads]                                  [Route: /account/dashboard]
           (Name: admin.leads.index)                            (Name: acme_portal.web.account.dashboard)
                         |                                                         |
         +-------------------------------+                         +-------------------------------+
         |  Root Web Package Resolver    |                         |  Root Web Package Resolver    |
         |  Checks:                      |                         |  Checks:                      |
         |  - str_starts_with name? NO   |                         |  - str_starts_with name? YES  |
         |  - middleware match? NO       |                         |  Matches! Priority 50         |
         |  - prefix !== ''? NO          |                         +-------------------------------+
         |  Result: FALSE (Pass Through) |                                         |
         +-------------------------------+                             Redirects to Portal Login
                         |                                                [customer.login]
         +-------------------------------+
         |  Admin Resolver Rule          |
         |  Priority -100                |
         |  Result: TRUE                 |
         +-------------------------------+
                         |
             Redirects to Admin Login
            [admin.session.create]
```

### Resolver Implementation in `WebServiceProvider::boot()`
```php
if ($this->app->bound(AuthenticationRedirectResolver::class)) {
    $prefix = (string) config('{{ PACKAGE_KEY }}_web.prefix', '{{ PACKAGE_SLUG }}');
    $this->app->make(AuthenticationRedirectResolver::class)->register(
        '{{ PACKAGE_KEY }}_web',
        function (Request $request) use ($prefix): bool {
            $route = $request->route();

            if ($route) {
                $name = (string) $route->getName();
                if ($name !== '' && str_starts_with($name, '{{ PACKAGE_KEY }}.web.')) {
                    return true;
                }

                $middleware = is_array($route->middleware()) ? $route->middleware() : [];
                if (in_array('{{ PACKAGE_KEY }}_auth', $middleware, true)) {
                    return true;
                }

                // Resolved route belongs to another package or Admin; do not intercept
                return false;
            }

            $normalized = trim($prefix, '/');
            if ($normalized !== '') {
                return $request->is($normalized) || $request->is($normalized . '/*');
            }

            return false;
        },
        function () use ($loginRoute): string {
            return route($loginRoute);
        },
        50
    );
}
```

## 7. Diagnostic Validation Matrix

| Misconfiguration Scenario | Thrown Diagnostic Error |
| :--- | :--- |
| Guard not defined in `config/auth.php` | `Authentication configuration error: Package [%s] specifies guard [%s], which is not defined in config/auth.php.` |
| Guard has undefined user provider | `Authentication configuration error: Package [%s] specifies guard [%s] with undefined user provider [%s] in config/auth.php.` |
| Provider package not active in `.env` | `Authentication configuration error: Package [%s] requires authentication provider package [%s], which is not currently enabled in LARASEED_OPTIONAL_PACKAGES.` |
| Missing login route | `Authentication configuration error: Package [%s] requires a configured login route when authentication is enabled.` |
| Login route name does not exist | `Authentication configuration error: Package [%s] requires a valid named login route, but route [%s] is not defined.` |
| Logout route does not accept `POST` | `Authentication configuration error: Package [%s] configured logout route [%s], but it does not support HTTP POST with CSRF protection.` |
