## 1. Executive Summary

Phase G05 delivers a clean, scalable, package-owned reusable UI component foundation and developer experience enhancements for the `starter` Web template generated by `php artisan laraseed:make-web`.

Key accomplishments in G05:
1. **Pre-Implementation Safety Verification & Redirect Hardening:** Verified route ownership in `AuthenticationRedirectResolver` against overlapping URL prefixes (e.g. `/shop`, `/shop/admin/orders`, and root `/`). Hardened the resolver rule to immediately return `false` whenever `$request->route()` is resolved and does not match the Web package's own route name prefix (`{package_key}.web.*`) or middleware (`{package_key}_auth`).
2. **Package-Owned Component Library:** Introduced a foundational set of 6 reusable Blade components adhering to Webkul Admin architectural conventions, packaged directly in `src/Web/Resources/views/components/`:
   - `<x-{{ PACKAGE_KEY }}_web::container>`
   - `<x-{{ PACKAGE_KEY }}_web::section>`
   - `<x-{{ PACKAGE_KEY }}_web::card>`
   - `<x-{{ PACKAGE_KEY }}_web::button>`
   - `<x-{{ PACKAGE_KEY }}_web::modal>`
   - `<x-{{ PACKAGE_KEY }}_web::form.control-group>`
3. **Dynamic Navigation & Active State:** Configured package navigation items centrally in `config/web.php` (`navigation` array), dynamically rendering in both the desktop navbar and mobile drawer with automatic active state highlighting via `request()->routeIs()`.
4. **Branding Customization:** Integrated declarative branding options (`branding.name`, `branding.color`, `branding.logo`) in `config/web.php` with dynamic CSS variable injection (`--brand-color`) into the master layout `:root` styles.
5. **Standardized Custom Page Flow:** Verified and documented the step-by-step Laravel-native workflow for developers extending generated packages with custom views, controller actions, routes, and translations.
6. **Zero Foundation Modification:** Maintained complete isolation; zero changes to `packages/Webkul/*` or `packages/Laraseed/Contacts`.

## 2. Pre-Implementation Safety Check & Redirect Isolation Audit

### 2.1 Overlapping Prefix Risk Analysis
In Laravel applications hosting both Admin and Web capabilities (or multiple Web packages), overlapping URL prefixes present a potential route hijacking risk if redirect resolvers rely on URL string prefixes rather than resolved route objects:
- Example: A Web package mounted at `/shop` with routes like `/shop/account/dashboard` vs an Admin package managing `/shop/admin/orders` or `/admin/login`.
- If unauthenticated requests hit `/shop/admin/orders`, a naive URL prefix check `$request->is('shop/*')` would falsely claim the request for the Web package's login route instead of the Admin login route.

### 2.2 Route-Resolved Ownership Resolution
The resolver rule in `provider.php.stub` was hardened to enforce strict resolved-route ownership:
```php
$resolver->addRule(function ($request) {
    if (! config('{{ PACKAGE_KEY }}_web.auth.enabled', false)) {
        return false;
    }

    $route = $request->route();
    if ($route !== null) {
        $name = $route->getName();
        if ($name && str_starts_with($name, '{{ PACKAGE_KEY }}.web.')) {
            return route(config('{{ PACKAGE_KEY }}_web.auth.login_route'));
        }

        $middlewares = $route->gatherMiddleware();
        if (in_array('{{ PACKAGE_KEY }}_auth', $middlewares, true)) {
            return route(config('{{ PACKAGE_KEY }}_web.auth.login_route'));
        }

        // When the route is resolved and does NOT belong to this package,
        // do not fall back to prefix matching (prevents hijacking sub-routes like /shop/admin/*)
        return false;
    }

    // Fallback only when route is null (pre-routing or synthetic requests)
    $prefix = trim(config('{{ PACKAGE_KEY }}_web.routing.prefix', '{{ PACKAGE_KEY }}'), '/');
    if ($prefix !== '' && ($request->is($prefix) || $request->is($prefix . '/*'))) {
        return route(config('{{ PACKAGE_KEY }}_web.auth.login_route'));
    }

    return false;
});
```

### 2.3 Verification Results
- **Overlapping Prefixes:** Requesting an unauthenticated Admin route under `/shop/admin/orders` resolves correctly to Admin's login (`/admin/login`). Requesting `/shop/account/dashboard` redirects to `/shop/login`.
- **Root-Mounted Isolation:** A Web package mounted at `/` (`prefix => ''`) does not intercept `/admin/*` unauthenticated requests.
- **Multi-Package Web Isolation:** Multiple Web packages with different prefixes and guards redirect exclusively to their own configured login routes without cross-contamination.

## 3. Package-Owned Reusable UI Component Library

All components reside in `packages/Laraseed/PackageGenerator/stubs/templates/starter/` and are generated into `<package>/src/Web/Resources/views/components/`.

### 3.1 Component Inventory

| Component | Stub Name | Tag Name | Description & Features |
| :--- | :--- | :--- | :--- |
| **Container** | `component_container.blade.php.stub` | `<x-{{ key }}_web::container>` | Responsive page width wrapper (`max-w-7xl mx-auto px-4 sm:px-6 lg:px-8`). |
| **Section** | `component_section.blade.php.stub` | `<x-{{ key }}_web::section>` | Content section supporting optional `$title`, `$description`, and `$actions` slots with light/dark borders. |
| **Card** | `component_card.blade.php.stub` | `<x-{{ key }}_web::card>` | Rounded card container with dark mode support, hover transition options, and optional `$header` and `$footer` slots. |
| **Button** | `component_button.blade.php.stub` | `<x-{{ key }}_web::button>` | Versatile button/link component supporting `variant` (`primary`, `secondary`, `outline`, `danger`), `size` (`sm`, `md`, `lg`), `href`, and `type`. Uses `--brand-color` for primary styling. |
| **Modal** | `component_modal.blade.php.stub` | `<x-{{ key }}_web::modal>` | Accessible modal dialog with backdrop, escape key handler, slot for body and optional `$header` and `$actions` slots. |
| **Form Control Group** | `component_form_control_group.blade.php.stub` | `<x-{{ key }}_web::form.control-group>` | Form field wrapper with `$label`, required asterisk (`$required`), slot for input/select, and automated validation error display (`$name`). |

## 4. Navigation & Branding Customization

### 4.1 Configuration Schema (`config/web.php`)
```php
return [
    'enabled' => true,

    'branding' => [
        'name'  => '{{ PACKAGE_TITLE }}',
        'color' => '#3b82f6',
        'logo'  => null,
    ],

    'routing' => [
        'prefix'     => '{{ PACKAGE_KEY }}',
        'middleware' => ['web'],
    ],

    'navigation' => [
        [
            'key'    => 'home',
            'label'  => '{{ PACKAGE_KEY }}_web::app.nav.home',
            'route'  => '{{ PACKAGE_KEY }}.web.home',
            'active' => '{{ PACKAGE_KEY }}.web.home',
        ],
        [
            'key'    => 'about',
            'label'  => '{{ PACKAGE_KEY }}_web::app.nav.about',
            'route'  => '{{ PACKAGE_KEY }}.web.page',
            'params' => ['slug' => 'about'],
            'active' => '{{ PACKAGE_KEY }}.web.page',
        ],
    ],
];
```

### 4.2 Dynamic Active State Detection
In both `navbar.blade.php` and `header.blade.php`, navigation items are rendered using:
```blade
@php
    $isActive = isset($item['active']) && request()->routeIs($item['active']);
    $url = isset($item['route']) ? route($item['route'], $item['params'] ?? []) : ($item['url'] ?? '#');
@endphp
<a href="{{ $url }}"
   class="px-3 py-2 rounded-md text-sm font-medium transition-colors {{ $isActive ? 'text-blue-600 dark:text-blue-400 font-semibold' : 'text-gray-700 hover:text-blue-600 dark:text-gray-300 dark:hover:text-white' }}">
    {{ trans($item['label'] ?? '') }}
</a>
```

### 4.3 Dynamic Branding & CSS Variables
In `layout.blade.php`, the configured brand color is injected into `:root`:
```blade
<style>
    :root {
        --brand-color: {{ config('{{ PACKAGE_KEY }}_web.branding.color', '#3b82f6') }};
    }
</style>
```
The header dynamically checks for `config('{{ PACKAGE_KEY }}_web.branding.logo')` to render custom SVG/image logos with automatic fallback to the package branding name and SVG icon.

## 5. Developer Workflow: Adding a Custom Page

Adding a new custom web page to a generated Web package is entirely native to Laravel:

```
+-----------------------------------------------------------------------------------+
|                           DEVELOPER PAGE CREATION FLOW                            |
+-----------------------------------------------------------------------------------+
| 1. Create View:        src/Web/Resources/views/pages/contact.blade.php            |
| 2. Add Route:          src/Web/Routes/web.php -> Route::get('contact', ...)       |
| 3. Register Nav Item:  config/web.php -> 'navigation' array                       |
| 4. Add Translations:   src/Web/Resources/lang/en/app.php & ar/app.php             |
| 5. Verify & Test:      Feature test HTTP GET & asset compilation                 |
+-----------------------------------------------------------------------------------+
```

### Step-by-Step Example
1. **Create View** (`src/Web/Resources/views/pages/contact.blade.php`):
   ```blade
   <x-portal_web::layouts.master title="Contact Us">
       <x-portal_web::container class="py-12">
           <x-portal_web::section title="Contact Us" description="Reach out to our team.">
               <x-portal_web::card>
                   <p>Contact form goes here.</p>
               </x-portal_web::card>
           </x-portal_web::section>
       </x-portal_web::container>
   </x-portal_web::layouts.master>
   ```
2. **Add Route** (`src/Web/Routes/web.php`):
   ```php
   Route::get('contact', function () {
       return view('portal_web::pages.contact');
   })->name('portal.web.contact');
   ```
3. **Register in Navigation** (`config/web.php`):
   ```php
   [
       'key'    => 'contact',
       'label'  => 'portal_web::app.nav.contact',
       'route'  => 'portal.web.contact',
       'active' => 'portal.web.contact',
   ],
   ```
4. **Add Translation Keys** (`src/Web/Resources/lang/en/app.php` & `ar/app.php`):
   ```php
   'nav' => [
       'contact' => 'Contact Us',
   ],
   ```
5. **Run Tests:** All views, routes, and navigation items render cleanly with matching active state.
