# CAMPUSHUB — PHASE 14 STEP 02: LOSTANDFOUND PUBLIC READ CONTRACT & WEBSITE PRESENTATION ADAPTER REPORT

## 1. Executive Summary

Phase 14 Step 02 successfully designed, implemented, and certified the cross-package boundary between `Webkul\LostAndFound` and `Webkul\Website`.

This step introduces a clean, read-only architectural capability allowing `Webkul\Website` to present public-safe Lost and Found information on the campus homepage without leaking any persistence models, repositories, database schema, employee identities, claimant records, or private details across package boundaries.

Key achievements:
- **Contract Boundary**: Created `Webkul\LostAndFound\Contracts\PublicLostAndFoundReadContract` and immutable DTO `Webkul\LostAndFound\DataTransferObjects\PublicFoundItemData`.
- **Zero Model Leakage**: Return types strictly return typed arrays of `PublicFoundItemData`. Zero Eloquent models, builders, or repositories are exposed to `Website`.
- **Consumer-Owns-Integration**: `Webkul\Website` owns its presentation via `Webkul\Website\Integrations\LostAndFound\WebsiteLostAndFoundServiceProvider` and Blade template `website::sections.lost-found`. `LostAndFound` contains zero Website views, sections, or styles.
- **Independence Preserved (Model B)**: `CAMPUSHUB_OPTIONAL_PACKAGES=website` remains 100% valid in isolation. Website core remains independent, activating its LostAndFound integration conditionally via explicit `OptionalPackageComposition` without runtime reflection hacks.
- **Physical Removability Certified**: Verified across all physical removal dry-run states (Cases A, B, C, D) on isolated replicas. Website boots without error when `LostAndFound` is physically absent from disk, and business packages boot when `Website` is deleted.
- **Full Test Suite Integrity**: The entire test suite grew from 536 passed tests (3,258 assertions) to **553 passed tests (3,350 assertions)** with 0 failures and 0 regressions.

## 5. Existing Public Visibility Rules

Inspection of domain rules in `FoundItem` and `ItemStatus` revealed:
- Item statuses: `DRAFT`, `REPORTED`, `IN_CUSTODY`, `RETURNED`, `DISPOSED`.
- Invariants:
  - Items in `DRAFT` status are incomplete staff drafts and must never be exposed publicly.
  - Items in `RETURNED` or `DISPOSED` are in terminal states (already returned to claimant or safely disposed) and should not be displayed as active items available for claim.
  - Items in `REPORTED` or `IN_CUSTODY` are active, verified items that are eligible for public display.
  - Categories have `is_active` boolean; inactive categories must not have their category codes shown publicly.

---

## 6. Existing Image Visibility Rules

Inspection of `FoundItemImageService.php`, `FoundItemImage.php`, and `FoundItemImageVisibility.php` revealed:
- `FoundItemImageVisibility` defines two cases: `PUBLIC_SAFE = 'public_safe'` and `STAFF_ONLY = 'staff_only'`.
- `STAFF_ONLY` images are stored strictly on disk `'lost_found_private'` (`storage/app/lost-found-private`) and must never have public URLs generated.
- `PUBLIC_SAFE` images are stored on disk `'public'` (`lost-found/items/public/*`) and can be safely accessed via `Storage::disk('public')->url(...)`.
- `FoundItem::coverImage()` has an existing scope restricting image selection to `visibility = 'public_safe'`.
- Security rule: If no `PUBLIC_SAFE` cover image exists, `has_image` is `false` and `image_url` is `null`.

## 9. Integration Activation Decision

Architecture analyzed:
- **Model A**: Make `Website` require `LostAndFound` directly in `composer.json`.
  *Drawback*: Invalidates `CAMPUSHUB_OPTIONAL_PACKAGES=website` and forces Website deployments to include `LostAndFound` and `Student`.
- **Model B (Selected)**: Website core remains independent. The LostAndFound presentation adapter is encapsulated in `Webkul\Website\Integrations\LostAndFound\WebsiteLostAndFoundServiceProvider` and registered conditionally by `WebsiteServiceProvider` when `lost_and_found` is present in `OptionalPackageComposition::enabledPackages()`.
  *Advantage*: Preserves `CAMPUSHUB_OPTIONAL_PACKAGES=website` validity. Prevents class autoload failures when `LostAndFound` is physically deleted. Requires zero runtime reflection hacks (`class_exists`, `Schema::hasTable`, `Route::has`).

## 13. Public DTOs

Path: `packages/Webkul/LostAndFound/src/DataTransferObjects/PublicFoundItemData.php`

```php
namespace Webkul\LostAndFound\DataTransferObjects;

use DateTimeInterface;
use Illuminate\Contracts\Support\Arrayable;
use JsonSerializable;

readonly class PublicFoundItemData implements Arrayable, JsonSerializable
{
    public function __construct(
        public string $reference,
        public string $title,
        public ?string $category = null,
        public ?string $foundLocation = null,
        public ?DateTimeInterface $foundAt = null,
        public ?string $description = null,
        public ?string $imageUrl = null,
        public bool $hasImage = false,
    ) {}

    public function toArray(): array
    {
        return [
            'reference'      => $this->reference,
            'title'          => $this->title,
            'category'       => $this->category,
            'found_location' => $this->foundLocation,
            'found_at'       => $this->foundAt?->format('Y-m-d H:i:s'),
            'description'    => $this->description,
            'image_url'      => $this->imageUrl,
            'has_image'      => $this->hasImage,
        ];
    }

    public function jsonSerialize(): array
    {
        return $this->toArray();
    }
}
```

## 15. Contract Implementation

Path: `packages/Webkul/LostAndFound/src/Services/PublicLostAndFoundService.php`
- Implements `PublicLostAndFoundReadContract`.
- Restricts queried statuses to `ItemStatus::REPORTED` and `ItemStatus::IN_CUSTODY`.
- Clamps query limit between 1 and 24 (`max(1, min($limit, 24))`).
- Selects only the 8 minimal columns needed for cards.
- Eager-loads only active categories and `PUBLIC_SAFE` cover images.
- Maps results to immutable `PublicFoundItemData` DTOs.
- Bound as a singleton in `packages/Webkul/LostAndFound/src/Providers/LostAndFoundServiceProvider.php`.

## 16. Query Design

The contract implementation executes optimal SQL queries utilizing existing table indexes:
```sql
SELECT id, public_reference, category_id, title, public_description, found_location, found_at, status
FROM lost_found_items
WHERE status IN ('reported', 'in_custody')
ORDER BY found_at DESC, id DESC
LIMIT 6;
```
- Eager loads categories via `SELECT id, code, is_active FROM lost_found_categories WHERE id IN (...)`.
- Eager loads cover images via `SELECT * FROM lost_found_item_images WHERE found_item_id IN (...) AND visibility = 'public_safe'`.
- Index utilized: `['status', 'found_at']` composite index on `lost_found_items`.
- Total queries for section render: at most 3.
- N+1 query count: 0.

## 17. Image Safety

- Images with `visibility = 'staff_only'` are stored on `lost_found_private` and are never loaded or returned.
- Images with `visibility = 'public_safe'` are stored on `public` and exposed as public URLs (`Storage::disk('public')->url(...)`).
- Raw storage keys, private disk paths, and server filesystem paths are never exposed.
- If no public-safe cover image exists, `hasImage` is false and `imageUrl` is null; the presentation renders a clean placeholder/icon.
