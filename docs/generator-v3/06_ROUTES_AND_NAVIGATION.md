# Laraseed Generator V3 — Routes, Navigation & Domain Mounting

This document details route registration, URL prefixing, root domain mounting (`/`), navigation menu configuration, active link detection, and multi-package coexistence rules in **Laraseed Generator V3**.

---

## 1. Route Architecture & Prefixes

By default, every Web capability generated by Generator V3 isolates its routes under a dedicated URL prefix derived from the package slug:

```
http://example.com/{package-slug}/
```

For example, a package created as `Acme/Portal` registers routes under `/acme-portal`.

### Configuration Contract (`src/Web/Config/web.php`)
```php
return [
    /**
     * Route prefix for Web capability.
     * Default: '{vendor-kebab}-{package-kebab}' (e.g. 'acme-portal')
     * Set to empty string '' to claim root domain route [/].
     */
    'prefix' => 'acme-portal',

    /**
     * Middleware stack applied to all Web capability routes.
     */
    'middleware' => ['web'],
];
```

### Route Grouping in `WebServiceProvider::boot()`
```php
if (file_exists(__DIR__ . '/../Routes/web.php')) {
    $prefix = (string) config('{{ PACKAGE_KEY }}_web.prefix', '{{ PACKAGE_SLUG }}');
    $middleware = config('{{ PACKAGE_KEY }}_web.middleware', ['web']);

    $normalizedPrefix = trim($prefix, '/');

    if ($normalizedPrefix === '') {
        $rootOwner = config('laraseed.web.root_owner');
        if ($rootOwner && $rootOwner !== '{{ PACKAGE_KEY }}') {
            throw new \RuntimeException(sprintf(
                'Route conflict: Package [%s] attempted to claim the root route [/], but it is already owned by [%s].',
                '{{ PACKAGE_KEY }}',
                $rootOwner
            ));
        }
        config(['laraseed.web.root_owner' => '{{ PACKAGE_KEY }}']);
    }

    Route::middleware($middleware)
        ->prefix($prefix)
        ->group(__DIR__ . '/../Routes/web.php');

    $this->app['router']->getRoutes()->refreshNameLookups();
    $this->app['router']->getRoutes()->refreshActionLookups();
}
```

## 2. Claiming the Root Domain (`/`)

To turn an optional package into the primary public website of the entire application, change its prefix to an empty string in `src/Web/Config/web.php`:

```php
'prefix' => '',
```

### Root Route Conflict Protection
If two different Web packages simultaneously set `'prefix' => ''`, the second package to boot will immediately throw an explicit `\RuntimeException`:

> `Route conflict: Package [beta_store] attempted to claim the root route [/], but it is already owned by [acme_portal].`

This prevents silent route overwriting and ensures predictable application booting.

## 3. Route Naming Standards

All Web routes generated within a package use the standardized named route prefix:  
`{package_key}.web.`

### Standard Starter Template Routes (`src/Web/Routes/web.php`)
```php
Route::name('{{ PACKAGE_KEY }}.web.')->group(function () {
    // 1. Homepage: GET /{prefix}
    Route::get('/', [HomeController::class, 'index'])->name('home');

    // 2. Dynamic Content Pages: GET /{prefix}/pages/{page?}
    Route::get('pages/{page?}', [PageController::class, 'show'])->name('pages.show');

    // 3. Optional Protected Dashboard: GET /{prefix}/account/dashboard
    if ((bool) config('{{ PACKAGE_KEY }}_web.auth.enabled', false)) {
        Route::middleware('{{ PACKAGE_KEY }}_auth')->group(function () {
            Route::get('account/dashboard', [AccountController::class, 'dashboard'])->name('account.dashboard');
        });
    }
});
```

#### Generated Named Route Examples for `Acme/Portal`:
- `acme_portal.web.home` -> `/acme-portal`
- `acme_portal.web.pages.show` -> `/acme-portal/pages/{page}`
- `acme_portal.web.account.dashboard` -> `/acme-portal/account/dashboard`

## 4. Navigation Menu Configuration

Navigation links for both desktop and mobile headers are declared centrally in `src/Web/Config/web.php` under the `navigation` array:

```php
'navigation' => [
    'home' => [
        'name'  => 'acme_portal_web::app.web.home',
        'route' => 'acme_portal.web.home',
        'sort'  => 1,
    ],
    'about' => [
        'name'   => 'acme_portal_web::app.web.about',
        'route'  => 'acme_portal.web.pages.show',
        'params' => ['page' => 'about'],
        'sort'   => 2,
    ],
    'features' => [
        'name'   => 'acme_portal_web::app.web.features',
        'route'  => 'acme_portal.web.pages.show',
        'params' => ['page' => 'features'],
        'sort'   => 3,
    ],
    'contact' => [
        'name'   => 'acme_portal_web::app.web.contact',
        'route'  => 'acme_portal.web.pages.show',
        'params' => ['page' => 'contact'],
        'sort'   => 4,
    ],
],
```

### Adding a New Navigation Link
To add a link to a new page (e.g. `pricing`):

1. **Add to `config/web.php`:**
   ```php
   'pricing' => [
       'name'   => 'acme_portal_web::app.web.pricing',
       'route'  => 'acme_portal.web.pages.show',
       'params' => ['page' => 'pricing'],
       'sort'   => 5,
   ],
   ```

2. **Add translation keys:**  
   In `src/Web/Resources/lang/en/app.php`:
   ```php
   'pricing' => 'Pricing',
   ```
   In `src/Web/Resources/lang/ar/app.php`:
   ```php
   'pricing' => 'الأسعار',
   ```

## 5. Active Link Detection Mechanism

In `navbar.blade.php` and `header.blade.php`, the template sorts navigation items by `sort` and dynamically calculates the `$isActive` state:

```blade
@php
    $navItems = collect(config('{{ PACKAGE_KEY }}_web.navigation', []))
        ->sortBy('sort', SORT_NUMERIC)
        ->all();
@endphp

@foreach ($navItems as $item)
    @php
        $routeName = $item['route'] ?? null;
        $params = $item['params'] ?? [];
        $url = $routeName && \Illuminate\Support\Facades\Route::has($routeName)
            ? route($routeName, $params)
            : ($item['url'] ?? '#');

        $isActive = false;
        if ($routeName && request()->routeIs($routeName)) {
            // If the route has route parameters (e.g. ?page=about), match exact parameter value
            if (empty($params) || (! empty($params['page']) && request()->route('page') === $params['page'])) {
                $isActive = true;
            }
        }
    @endphp

    <a
        href="{{ $url }}"
        class="transition-colors text-decoration-none {{ $isActive ? 'font-bold text-[var(--brand-color)] border-b-2 border-[var(--brand-color)] pb-1' : 'text-gray-700 hover:text-[var(--brand-color)] dark:text-gray-300 dark:hover:text-white' }}"
    >
        {{ trans($item['name'] ?? '') }}
    </a>
@endforeach
```

## 6. Multi-Package Coexistence Matrix

Multiple Web packages can be enabled simultaneously in `LARASEED_OPTIONAL_PACKAGES`:

```dotenv
LARASEED_OPTIONAL_PACKAGES=contacts,portal,store,docs
```

```
+-------------------+--------------------+------------------------+-------------------------------+
| Package           | Prefix             | Example Route          | Route Name                    |
+-------------------+--------------------+------------------------+-------------------------------+
| Acme/Portal       | '' (Root Mount)    | http://example.com/    | acme_portal.web.home          |
| Shop/Store        | 'store'            | http://example.com/store | shop_store.web.home          |
| Help/Docs         | 'docs'             | http://example.com/docs | help_docs.web.home           |
| Webkul/Admin      | 'admin'            | http://example.com/admin | admin.dashboard.index       |
+-------------------+--------------------+------------------------+-------------------------------+
```

Because all view components, controllers, route names, and asset builds are strictly namespaced, zero cross-contamination occurs.
